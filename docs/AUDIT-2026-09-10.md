# 🔴 CRITICAL

## C1 — Bypass token `autoRegisterOperator_` via placeholder
- [x] Selesai
- **Lokasi:** `gas/Code.gs:2199-2205` (`autoRegisterOperator_`)
- **Masalah:**
  ```js
  var EXPECTED_TOKEN = PropertiesService.getScriptProperties().getProperty('INTEGRATION_TOKEN') || "YOUR_INTEGRATION_TOKEN";
  if (data.token !== EXPECTED_TOKEN) { throw ... }
  ```
  Jika property `INTEGRATION_TOKEN` belum di-set, maka string placeholder `"YOUR_INTEGRATION_TOKEN"` **adalah** token yang sah. Endpoint ini ada di `PUBLIC_ACTIONS_` (bebas token sesi), sehingga **siapa pun** bisa mendaftarkan akun operator massal dengan password default hardcoded `"sianjabmj2026"` (`gas/Code.gs:2256`).
- **Dampak:** Pembuatan akun tidak sah + password default yang bisa dipakai login.
- **Perbaikan:**
  1. Fail-closed: jika `INTEGRATION_TOKEN` kosong/placeholder → `throw new Error("INTEGRATION_TOKEN belum dikonfigurasi di server")`.
  2. Hapus password default hardcoded; wajibkan `data.password` dikirim dari sistem pemanggil (atau generate acak + kirim via kanal terpisah).
  3. Tambah rate-limit sederhana (counter di CacheService per IP).

## C2 — Token sesi bisa dipalsukan (tidak ada HMAC)
- [x] Selesai
- **Lokasi:** `gas/Code.gs:163-193` (`validateToken_`), token dibuat di `loginUser_` (`gas/Code.gs:1160`): `Utilities.base64Encode(user.username + ':' + Date.now())`
- **Masalah:** Komentar di config mengaku "validasi token HMAC dengan API_SECRET", tetapi `API_SECRET` **tidak pernah dipakai**. Token hanyalah base64 `username:timestamp` — siapa pun yang tahu username (username = NIP pegawai) bisa membuat token valid sendiri. `validateToken_` hanya cek "user ada & aktif".
- **Dampak:** Autentikasi bisa dilewati sepenuhnya oleh siapa pun yang paham formatnya.
- **Perbaikan:**
  1. Saat login: `sig = Utilities.computeHmacSignature(Utilities.MacAlgorithm.HMAC_SHA_256, username + ':' + expiry, API_SECRET)`; token = `base64url(username:expiry:sig)`.
  2. Saat validasi: dekode, hitung ulang HMAC, bandingkan konstan; tolak jika `API_SECRET` kosong (fail-closed, hapus mode "backward compatible").
  3. Turunkan masa berlaku dari 7 hari → 1 hari (opsional tapi disarankan).

## C3 — Tidak ada otorisasi berbasis role sama sekali
- [x] Selesai
- **Lokasi:** `gas/Code.gs:220-410` (`handleRequest_` switch), `validateToken_` (163)
- **Masalah:** Setelah token valid, **semua action terbuka untuk semua role**. Operator biasa bisa memanggil: `createUser`, `updateUser`, `deleteUser`, `deleteYearData`, `syncFromSheet`, `cloneYearData`, `saveTemplate`, membaca `settings/aiConfig` (**bocor API key Gemini/OpenAI/DeepSeek ke semua operator**), dll.
- **Dampak:** Operator OPD bisa menghapus data tahunan, mengelola user, dan mencuri API key berbayar.
- **Perbaikan:**
  1. Definisikan `ADMIN_ONLY_ACTIONS_ = ['createUser','updateUser','deleteUser','deleteYearData','cloneYearData','syncFromSheet','syncToSheet','cleanupOrphanedRecords','migrateRootTo2026','saveTemplate','saveTagMappings','saveDeadline','saveAiConfig'... + action settings lain]`.
  2. Ubah `validateToken_` agar mengembalikan objek user (`{username, role, unitKerjaId}`), lalu di `handleRequest_` tolak dengan pesan "Akses ditolak: hanya admin" jika action admin-only dan role ≠ `admin`.
  3. Untuk action ber-scope unit (`getJabatanByUnit`, `saveABK`, `saveSingleEntity`, `saveMultiEntity`, `saveBulkAnjabData`): jika role operator, paksa `unitId`/`jabatanId` milik `user.unitKerjaId` (cek jabatan → unitKerjaId).
  4. Filter field sensitif: `readAllRecords_` untuk `settings` harus mem-strip `*ApiKey` untuk non-admin.

## C4 — Fitur verifikasi dokumen tidak benar-benar memverifikasi
- [x] Selesai
- **Lokasi:** `src/lib/verification.ts:95-155` (`generateVerificationCode`, `getVerificationRecord`), `src/app/verify/page.tsx:15-33`

Halaman `/verify` "memvalidasi" dengan meng-decode token base64 yang dikirim di URL yang sama (`?d=...`) — token itu menandatangani dirinya sendiri (`verification.ts:9-23`). - **Dampak:** Fitur keabsahan dokumen bersifat dekoratif; bisa dipakai memalsukan legitimasi dokumen.
- **Perbaikan:**
  1. Backend baru di GAS: action `registerVerificationCode` (dipanggil saat export docx, simpan record ke path non-yearly `verification_logs/<kode>` di Firebase) dan `checkVerificationCode` (baca by kode, token publik TIDAK dipercaya).
  2. Ubah `exportDocx.ts` agar memanggil registrasi server sebelum render footer.
  3. Ubah `verify/page.tsx`: hanya percaya hasil `checkVerificationCode`; token URL `d` boleh tetap untuk UX tapi tidak sebagai bukti.
  4. (Menengah) Tambah QR menuju URL verify berisi **kode saja**.

## C5 — `exportForSitpp_` menelenkan data lintas tahun (ID sama)
- [x] Selesai
- **Lokasi:** `gas/Code.gs:1282-1360` (`exportForSitpp_`, merge loop `years.forEach`)
- **Masalah:** `unitKerja`/`jabatan` dari tahun 2025–2030 di-merge ke satu map **ber-key Firebase push-ID**, lalu dikelompokkan per `tahun`. Karena `cloneYearData_` (`gas/Code.gs:2278`) menyalin record **dengan ID yang sama**, key yang sama tertimpa tahun terakhir yang discan — data tahun-tahun sebelumnya **hilang** dari ekspor SiTPP.
- **Dampak:** Ekspor nasional (SiTPP) kehilangan seluruh jabatan tahun lama secara diam-diam.
- **Perbaikan:** Pindahkan pengelompokan per tahun ke dalam loop scan: isi `opdListByTahun[yr]` / `orgMasterByTahun[yr]` **langsung saat membaca `yr/unitKerja` dan `yr/jabatan`** (jangan merge dulu). Gunakan opdKey = kode unit untuk mapping antar-record dalam **satu** tahun saja. Hapus map gabungan `allUnit/allJabatan`.
